# Never Stop 独立 Demo

复用 Vantage 的 Electron / React 依赖，提供独立桌面入口；不替换现有 Vantage 页面或后台。

## 启动

Windows 在仓库根目录双击 `NEVER_STOP.bat`。它构建 Demo 页面，再启动独立桌面进程，不运行 Vantage 的安装和发布流程。首次缺少依赖时自动安装现有前端锁文件中的依赖。需要已配置且在 PATH 可发现的 Claude Code 或 Codex 原生 `.exe`；首版不执行 npm `.cmd` 包装脚本，缺少原生程序会明确显示错误。

开发命令从仓库根目录执行：

```text
npm --prefix src/webapp ci
npm --prefix src/webapp run never-stop:build
npm --prefix src/webapp run never-stop:start
npm --prefix src/webapp run never-stop:test
npm --prefix src/webapp run never-stop:package
```

`never-stop:package` 生成独立 Windows portable EXE，输出在本目录 `release` 下。现有 CLI 的登录、模型、工具权限仍由用户自己的配置决定；Demo 不安装模型、不改账号、不添加绕过权限的参数。

## 使用

1. 添加已有项目根目录，或新建文件夹；也可只读发现本机 Claude Code / Codex 的历史项目目录。
2. 打开“目标”，编辑并保存 Markdown。自动保存只更新草稿；点击“发布”后执行器才使用它。
3. 点击开始。一次调用正常结束立即续跑；失败持续重试。Agent 说完成或自评 100% 都不会停止。
4. 点击暂停会先保存暂停意图，再中断本项目受管理的执行进程树。项目页空格可切换；编辑器、输入框和对话框内空格不会切换。
5. 发布新目标会中断旧调用并续接同一会话；重置上下文会使用新的会话。暂停中操作不会自行开始运行。
6. 关闭窗口仍在后台工作；系统托盘可重新打开，或“退出并暂停全部项目”。可在设置启用登录自启。

应用数据在平台用户应用数据目录的 `VantageNeverStop` 下。运行意图、已发布目标、会话 ID、错误摘要及资源保存在此；开发测试可通过 `NEVER_STOP_DATA_DIR` 使用隔离目录。项目移除只删除应用记录，保留源文件。

## 最新进度

项目页默认展开“实时运行”面板，显示 Claude Code / Codex 返回的助手消息、工具调用、结果和错误。Claude 启用 partial messages，在尚无完整段落时显示“正在思考 / 生成回复 / 生成工具参数”的状态；同阶段有新数据时最多每 5 秒更新已接收字符数（不是 token 数）。完整段落才经过脱敏显示一次，不逐字展示未完成文本，避免凭据跨分片泄露。断流时不会虚构心跳；长时间没有新状态也可能是预填充或等待网络，需要结合服务端记录判断。支持收起、暂停自动跟随、复制及清空显示；清空不影响任务或会话。

Claude 一轮调用必须收到成功的最终 `result` 事件才能认定正常结束；仅收到 `message_stop` 或进程退出码为 0 不足以证明调用完成。缺失最终结果会作为可见错误进入原有重试流程，旧执行树确认退出后才开始下一轮。原生 `stream_event` 错误、上下文压缩开始与完成也会显示状态。

Claude 的 `[claude-code:unrecognized_model]` 完整模型列表诊断显示为普通“状态”，说明自定义模型不在内置列表中，不代表调用失败。只有已知格式会被这样分类；真正的 API 错误、格式不符的输出仍显示为错误，模型提示不会覆盖真实失败详情，也不会改变调用成功判定。

活动只保留在内存中，每项目最多 300 条、256 KiB，后台总量最多 4 MiB；长输出和拥塞会省略并提示，退出应用后不保留。已知环境凭据、已选资源密码及常见凭据格式在显示前脱敏；不会展示内部推理事件。

项目页显示“累计运行”，运行中每秒更新，跨天显示天数。累计用户启动至暂停或退出的时间，包含自动重试和目标切换；发布目标、重置上下文和清空输出不会清零。暂停及应用离线期间不计，隐藏窗口仍继续累计。已有项目从安装支持计时的版本后开始记录，无法还原旧版未记录的时长。累计值定期保存，异常崩溃可能丢失最近约 15 秒。

项目路径旁的“更改目录”可重新选择工作文件夹。累计时间及项目记录保存在应用数据目录，切换后保留；原来运行的项目成功后继续，暂停项目仍暂停。新目录使用新 CLI 会话，保留已发布目标，不继承旧会话聊天上下文。

更改目录会把 `goal.md`、`progress.md`、`.never-stop/progress.json` 复制到新位置的空缺处，源文件保留。同名不同内容会报冲突，不会覆盖；请先自行核对并整理两个目录再重试。代码及其他项目文件不由应用搬运。若你已经手动移动文件夹，直接选择新位置即可；旧目录缺失时，无法恢复未随文件夹移动的未发布草稿，但可从应用保存的已发布目标恢复缺失的 `goal.md`。目标草稿有未保存编辑或冲突时，先保存或解决冲突再更改目录。

目录迁移不受 1 MiB 界面显示上限限制：大文件按完整字节复制并分块校验。超过显示上限的 `progress.md` 保留原文件，界面优先显示有效的进度 JSON 并提示；不会把大文件截成短摘要。目标编辑及结构化进度的显示上限仍为 1 MiB。

独立 Demo 当前打包版本为 1.0.81，与 Vantage 主应用版本独立，页面显示实际运行版本。更新时从旧版托盘选择“退出并暂停全部项目”，再打开新版 EXE；关闭窗口只会隐藏到后台。

新版正式应用启动时会按已保存设置同步启用中的自启动入口，Windows 使用固定条目名称，指向当前便携 EXE，不使用解压临时路径。保留系统任务管理器中的禁用状态；同步失败在设置页提示，不影响项目恢复。开发启动不自动登记，隔离数据目录的测试实例不修改真实自启动项。目前交付仍为便携 EXE，不包含联网检查、下载和安装新版的更新服务。

Agent 维护项目 `.never-stop/progress.json`。应用确定性生成 `progress.md`，界面标注“Agent 自评”。协议只检查显示数据，不判断业务成果是否合格。

```json
{
  "schema_version": 1,
  "updated_at": "2026-09-12T12:00:00+08:00",
  "overall_percent": null,
  "summary_markdown": "最新状态摘要",
  "radar": { "axes": [] },
  "suggestions_markdown": ""
}
```

以上日期仅演示格式，实际由 Agent 写入更新时间及当地时区。分数必须为 0–100 数字，整体可为 null。少于三个维度显示数据不足；不补造评分。文件上限 1 MiB、维度上限 24 项；协议错误保留上次有效数据。首次有效快照之前保留已有 `progress.md`。

UI 与外部编辑器同时编辑目标时检测内容版本冲突，展示本地和外部草稿供选择或手动合并；不会将外部草稿自动发布。

## 资源与凭据

在“我的资源”保存主机、用户名、密码或私钥路径，并为项目勾选。密码通过 Electron 平台安全存储加密，平台无安全存储时不接受密码保存。Agent 获得非秘密描述及实际可调用的本地辅助入口；命名管道授权令牌仅通过子进程环境传递。辅助入口执行 SSH，密码和私钥不作为提示词输出。

SSH helper 只接受已在本机 `known_hosts` 信任的主机密钥。SSH 配置导入对 Include、Match、通配符和代理选项提供限制提示，复杂配置仍可由 Agent 使用用户现有 SSH 工具。暂停只控制本地受管理进程；不保证终止远端自行脱离会话的作业。

## 验证与限制

默认测试使用临时目录和可控假 CLI，覆盖续跑、十次失败恢复、100% 不停止、多项目、发布、重置、真实 cwd、进程树、崩溃恢复、编辑冲突及无效进度数据。资源测试包含本机 SSH 服务与 helper 子进程的完整连接流程。测试程序不操作真实研究项目。

`test/desktop-smoke.cjs` 是显式运行的 Electron 集成检查，需要 Playwright，可通过 `PLAYWRIGHT_MODULE` 指定安装位置。真实 Agent 接入测试另见交付验证记录，不纳入默认测试以免反复消耗模型调用。

`test/live-output-smoke.cjs` 使用临时原生 CLI 验证运行未结束时输出可见、项目隔离、复制、折叠、清空和键盘操作。设置 `NEVER_STOP_ELECTRON` 可指定打包后的应用进行同一检查。

`test/lifecycle-smoke.cjs` 用 Node 可执行文件的临时硬链接替代 Claude，实际验证 Electron 窗口关闭继续、错误持续重试、崩溃重开和暂停持久化。需要使用可在临时目录创建硬链接的 Node 安装（部分 Windows 系统目录安装会拒绝）；不会调用模型。该测试和界面测试均使用隔离的应用数据目录。

Windows 为本次实际开发平台；macOS 和 Linux 未通过实机验证。Linux 登录自启尚未实现，会明确返回错误。第三方项目发现使用当前版本可读元数据，不是稳定 API；发现失败可手动选目录。系统通知受本机权限与勿扰设置影响，UI 区分已请求和系统确认显示。

Windows 使用受管理进程树强制结束作为中断实现。无法确认首轮是否建立会话时，会展示明确错误，要求用户重置上下文，避免静默丢失历史。磁盘无法保存运行意图时会停止本地执行并告知重启可能恢复旧意图；应恢复存储后重新保存控制操作。非 Windows 的文件锁恢复仍采取保守策略，未列入已验收平台。

固定执行原则位于 `never_stop_execution_principles_v0_1.md`。原需求只提供配套文件名而没有全文，此版本按需求中明确的原则整理；可以在 UI 只读查看实际发送内容。

## 后续嵌入 Vantage 的最小接口

- `core/runner.cjs`：独立运行器，维护用户意图、会话和执行进程。
- `core/application.cjs`：有限方法集合，将 UI 操作映射为运行器与文件操作。
- `preload.cjs`：`window.neverStop.invoke(method, payload)` 与 `onChange` 事件。
- `ui/main.jsx`：独立项目页面；嵌入时保留上述桥接即可。
- `main.cjs`：独立应用生命周期、托盘、目录选择、安全存储和通知。集成时移入 Vantage 已有主进程，保证全局只有一个该运行器实例，不能让页面挂载/卸载决定执行生命周期。

CLI 接口参考 [Claude Code 官方文档](https://code.claude.com/docs/en/cli-reference) 和 [Codex 非交互模式](https://developers.openai.com/codex/noninteractive)，实现还核对本机实际帮助输出。

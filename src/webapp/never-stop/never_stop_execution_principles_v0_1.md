# Never Stop 通用执行原则 v0.1

这是应用附带的普通用户指令，不能覆盖 Agent 本身的系统指令、安全要求和用户已有权限配置。

1. 使用中文沟通。围绕当前已发布目标持续采取有效行动，自行选择工具和组织工作。
2. 即使认为目标已满足，也在原目标范围内继续复核和完善。不得擅自扩大目标、降低用户要求或代替用户宣布最终批准。暂停由用户控制。
3. 不修改用户的 goal.md 或应用内已发布目标；需要改变目标时，将建议写入 suggestions_markdown，由用户自行决定是否发布。
4. 每次开始先读取 goal.md 并按照其中目标执行，再读取 progress.md 最新摘要和必要项目文件；如果 progress.md 与 goal.md 不一致，以 goal.md 为准纠正执行方向。重置上下文后同样遵循这一顺序，不假定仍记得旧对话。
5. 维护项目根目录 `.never-stop/progress.json` 的最新完整快照，使用临时文件加重命名尽量避免半写；不要不断追加历史。progress.md 由应用生成，不另写一份冲突状态。
6. 快照字段：schema_version 为数字 1；updated_at 为实际更新时间的 ISO 8601 日期（包含当地时区偏移）；overall_percent 为 0–100 数字或 null；summary_markdown 为最新摘要；radar.axes 为数组，每项包含非空 label 和 0–100 数字 value；suggestions_markdown 为建议文本，无建议时为空字符串。维度自行定义，最多 24 项。没有充分数据时填写 null 或空维度，不编造漂亮得分。
7. 分数和结论是 Agent 自评。简明记录已做、正在做、下一步及对继续工作有用的事实。详细材料保留在项目文件，摘要尽量一到两屏。
8. 资源描述只给出可用连接信息及安全取用入口。不要将密码、私钥或取用令牌写入目标、进度、普通日志或 Git。沿用配置好的工具权限；访问被拒绝时如实报告，不修改账号和权限来绕过。
9. 报告真实工作结果和错误，不将尝试描述为已完成，不为了维持运行反复生成无意义内容。

持续续跑由应用运行器实现，这些原则本身不是永不退出机制。该模板按开发需求中明确的原则整理；原配套文件全文未随需求提供。

# 本地崩溃记录

Vantage 在桌面主进程启动时启用本地 Electron Crashpad，在 Python 后端入口导入服务之前启用 `faulthandler`。无需配置系统注册表，也不会自动上传诊断数据。

## 使用

- 在“设置 → 关于 → 本地崩溃记录”打开诊断目录。
- 目录位于配置的用户数据目录下的 `diagnostics/`，不会写入仓库。
- 独立运行安装版 CLI/MCP 同样默认使用用户数据目录；显式目录和运行模式仍优先。
- 下次启动发现上次桌面会话未正常结束时，显示可以关闭的提示，不阻止使用。
- 提示不能证明发生了程序崩溃：断电、强制结束进程也会留下未完成标记。

## 内容与隐私

- `electron/`：Electron 主进程、渲染进程及原生子进程的崩溃转储。
- `python/`：后端及打包子命令的原生故障堆栈、未捕获异常和线程异常。异常记录不写异常值、源码行或局部变量。
- `incidents/`：异常退出的时间、进程类别、固定原因枚举及退出码。不写请求参数、服务名称或异常消息。
- 会话标记用于区分正常结束与未正常结束，不包含用户业务数据。

**转储可能包含内存中的密钥、提示词及其他隐私。堆栈也可能包含本机路径。分享前必须检查，不要提交到公开仓库。**

启动及运行期间清理旧记录：已完成文件合计最多 10 个、总计 200 MiB。正在使用的文件和刚写入的原生转储受到保护；活跃文件可能暂时超过容量，完成后再清理。清理不会遍历符号链接或目录联接。权限、磁盘等记录故障不会阻止应用启动。

本功能是保留故障证据，不是自动修复、自动重启或崩溃原因判定器。强制终止、断电及某些无法执行故障处理器的情况可能只有退出标记而没有堆栈或转储。

## 开发验证

从仓库根目录运行对应虚拟环境中的 Python 测试，并运行前端检查。原生崩溃验证只使用临时目录与独立子进程，不触碰正在运行的安装版或真实业务数据。

```powershell
python -m pytest -q tests/test_crash_diagnostics.py
npm --prefix src/webapp run check
npm --prefix src/webapp run test:electron-ui
npm --prefix src/webapp run test:crash-diagnostics
```

最后一个命令故意令独立 Electron 测试进程崩溃；测试父进程验证本地转储、禁止上传、下一次会话恢复与正常退出标记。

Windows 打包 CLI 的独立目录验证（临时用户目录和模拟后端，不调用业务工具）：

```powershell
node src/webapp/scripts/smoke-packaged-crash-diagnostics.cjs "path/to/VantageBackend.exe"
```
